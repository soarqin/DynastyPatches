# Swordman 中途存档

目标为 `Sm_win2.exe`，SHA-256 为 `2ad46144eaca95b92a7d28ad946687df09fb0c3155cf3ccafa8381fba53afbb2`，ImageBase 为 `0x00400000`。以下地址均为该版本的 VA。

## IDA 证据

使用注册表中安装的 IDA Professional 9.4（`C:\Software\IDAPro94\idat.exe`）分析。完整反汇编、原始字节和 XREF 保存在 `analysis/swordman_save_anytime.txt`；关卡状态机保存在 `analysis/swordman_stage_update.txt`。导出脚本为 `tools/ida_swordman_evidence.py` 和 `tools/ida_swordman_range.py`。

## 存档格式与调用链

- `0x00417500`：读取 `GAMEDATA.GCF`；标题画面继续游戏和战斗内读档均调用此函数。
- `0x00417710`：写入 `GAMEDATA.GCF`，随后由 `0x00416C50` 对文件逐字节异或 `0xA5`。读取时由 `0x00416D90` 解码。
- 解码后的文件依次为：两个 32 位记录数（`0x08` 字节）、`CGameController`（`0xF20` 字节）、地图位置（`0x08` 字节）、光标位置（`0x08` 字节）、角色记录（每项 `0x25C` 字节）、地图事件记录（每项 `0x0E` 字节）。角色记录起点为 `0xF38`。
- `0x0044A890 → 0x00449260 → 0x0042A8E0 → 0x0042A5A0 → 0x00424270`：从存档恢复角色；`0x004242A5` 完整复制 `0x25C` 字节，随后重建运行时资源指针。

角色记录的 `+0x0A` 是 16 位可行动标志（`1` 为可行动，`0` 为已行动）；`+0x1A`、`+0x1C`、`+0x1E` 为移动力相关字段。`0x00445A30` 在行动结束时清除 `+0x0A`，并更新移动力与显示效果。

## 原有限制与恢复问题

`0x00446380` 检查在场、我方且受玩家控制的角色；任一角色已行动时返回 `0`。调用者 `0x004463D0` 将结果传入系统菜单，最终控制存档菜单项是否可用。该函数只有这一个调用点。

成功读档后，`0x0044A936` 将关卡状态置为 `9`。后续状态机在 `0x0044A610` 调用 `0x0044A2C0`，把我方可控角色的 `+0x0A` 重置为 `1`，并重算 `+0x1A`、`+0x1E`。存档保存的行动状态因此丢失。该初始化函数只有这一处调用点，但正常回合也通过同一状态机调用它。

## 运行时补丁

| hook 位点 | 校验的完整指令字节 | 行为 |
| --- | --- | --- |
| `0x00446380` | `8B 89 88 00 00 00` | 存档条件函数返回 `1`，允许行动后保存。 |
| `0x0044A936` | `C7 46 0C 09 00 00 00` | 记录成功读入的关卡指针，保留原来的状态赋值，续接 `0x0044A93D`。 |
| `0x0044A2C7` | `33 FF 8B 45 18` | 仅对刚读入的同一关卡跳过一次重置循环，续接 `0x0044A341`，继续输入初始化。其他调用经 MinHook trampoline 执行原逻辑。 |

`0x0044A2C7` 前已建立原函数栈帧并保存 `EDI`；跳过循环时尚未压入循环专用的 `EBX`、`ESI`，与 `0x0044A341` 的栈布局一致。hook 保留寄存器和 EFLAGS，并在匹配关卡时消耗一次性标记。角色记录无需扩展，文件格式不变。
