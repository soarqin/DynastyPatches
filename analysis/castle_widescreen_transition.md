# Castle 宽屏双向灰度转场

分析日期：2026-10-09。基准文件为 `E:/Games/Dynasty/Castle/exe/RPG.exe`，SHA-256 为 `8294839343b1a7845ddae31ed16216b05850efd39a742e5ca7701aadca97287f`。使用 Windows 注册表找到的 IDA Pro 9.4，通过 Python `idapro` 分析 `build/ida-castle-backdrop/` 中的副本。

地图进入菜单、商店和存读档界面时，逐渐过渡为灰度暗化地图；关闭界面并返回原地图时，反向恢复彩色。菜单元素向两侧展开期间保留菜单原有背景，菜单销毁后再接入灰度地图。战斗使用原有过渡特效，地图之间切换和读档继续使用原有黑屏逻辑。Bink 和脚本自定义颜色、反色效果沿用原有路径。

辅助脚本为 `tools/ida_castle_transition.py`，可复现函数反编译、调用关系、vtable、全局字段和 hook 入口字节。原始输出 `analysis/castle_transition_ida.txt`、`analysis/castle_transition_opcodes.txt` 为本地分析产物；本文件保存实现需要的证据。未运行游戏或 `idat`。

## 地图淡出淡入

`sub_406F20(step, delay)` 只在状态 1 开始淡出，将状态改为 3，亮度置 15、终点置 0、颜色置 1；状态 7 时返回完成。`sub_406EE0(step, delay)` 在状态 7 开始淡入，将状态改为 2；状态 1 时返回完成。`sub_406BF0` 推进亮度和状态。补丁保留这些函数的参数、状态写入和返回值，仅观察目标场景。

| 地址 | 含义 |
| --- | --- |
| `0x00468AE8` | 效果状态：1 正常、2 淡入、3 淡出、4 反色、6 自定义颜色、7 保持 |
| `0x00468AEC` | 当前亮度，普通转场范围 0 至 15 |
| `0x0089F7A0` | 效果颜色，普通黑屏淡出为 1 |
| `0x0089F804` | 当前地图对象 |
| `scene + 0x219` | 地图绘制禁止标志 |
| `0x0089F80C / 0x0089F810` | 当前事件命令数、命令索引 |
| `0x0089F814 / 0x0089F820` | 命令偏移表、脚本缓冲区 |
| `0x0089F830` | 当前命令对象，其 `+4` 指向命令记录 |

`sub_406DA0` 仅在地图绘制函数的 `0x0040B07D` 被调用。已有 NASM 缓存 hook 在该调用前保存原始地图，随后新函数 hook 按转场权重处理 CPU 像素。无匹配的转场状态、反色或自定义颜色时，继续执行 MinHook trampoline。

`sub_40B150` 在逻辑更新中调用 `sub_406BF0`；状态 7 的等待、下一条脚本命令和淡入结束条件保持不变，避免修改视觉后脚本一直等待完成。

## 区分固定界面与换地图

命令记录首个 DWORD 为 opcode。`sub_40B3B0` 创建命令对象并设置其 `+4`，返回前执行 vtable 初始化入口。命令第一次实际执行时，可能尚未写入 `0x0089F830`；因此 factory hook 在调用原函数期间保存当前 opcode，后续执行再读全局命令对象。

| opcode | 执行入口 | 用途 |
| --- | --- | --- |
| `0x35` | `0x0040CBF0` | 系统菜单，自带淡出和淡入 |
| `0x36` | `0x0040D120` | 普通菜单，无原生地图淡出和淡入 |
| `0x37` | `0x0040D200` | 剧情战斗，进入动画独立于通用淡出 |
| `0x39` | `0x0040D510` | 存读档界面，部分事件在前一条命令淡出 |
| `0x3E` | `0x0040DAA0` | 商店，自带淡出和淡入 |
| `0x3A / 0x3B / 0x3C` | `0x0040D780 / 0x0040D8A0 / 0x0040D9C0` | 加载、压入或移除地图 |
| `0x53 / 0x5A` | `0x0040DF20 / 0x0040E1B0` | 通用淡出 |
| `0x54 / 0x5B` | `0x0040DF90 / 0x0040E230` | 通用淡入 |
| `0x8C` | `0x0040ED70` | 按保存的信息重建地图 |
| `0x8D` | `0x0040EDB0` | 标题菜单等独立界面 |
| `0x98` | `0x0040F4A0` | Bink 视频 |

通用淡出只在后续直线命令明确指向固定界面时启用灰度转场。前瞻最多 16 条，只允许经过已确认的等待命令 `0x01`；遇到分支、结束、未知命令或地图加载立即停止。`0x47` 至 `0x4D` 是条件跳转，不能误当作音频操作而越过。读取前核对已提交的内存区域、偏移表长度和记录边界。

本机地图事件文件中，系统菜单 opcode 共 319 处，普通菜单 59 处、剧情战斗 107 处、存读档 8 处、商店 17 处。7 处存读档界面明确使用 `0x53 -> 0x39`；常见地图切换为 `0x53 -> 0x3A -> 0x54`，不能共用灰度转场。该统计用于检查已知资源路径，不用于放宽运行时的直线前瞻规则。

地图加载函数 `sub_40AF40`、读档成功后的 `sub_43B510`，以及地图切换、标题菜单和视频命令都会清除灰度状态和快照。`sub_44B1F0` 即使返回同一地图名称，也会创建新的地图对象，加载 hook 同样取消灰度；旧对象延迟析构只清除属于旧对象的快照。

## 菜单关闭后的遮屏层

系统菜单由 `sub_434920` 创建。`menu + 0x5F4` 指向 `Fight\Other\FANIN.SF2` 的遮屏对象，`menu + 0x5F8` 是关闭阶段。`sub_435AA0` 在阶段 1 启动遮屏对象，阶段 2 等待其完成，随后进入阶段 3 并销毁菜单。元素位置动画由 `sub_436340` 单独推进。

这层遮屏在地图停止绘制后仍单独绘制，地图效果 hook 无法处理它。上一版只替换地图的 `sub_406DA0`，因此菜单关闭期间仍会出现黑屏。

| 地址或偏移 | 含义 |
| --- | --- |
| `0x008DED0C` | 当前系统菜单对象 |
| `0x008E1C48` | 游戏状态对象 |
| `menu + 0x5F4 / 0x5F8` | 返回遮屏对象、关闭阶段 |
| `ui + 0x564` | UI 对象的主精灵 |
| `ui + 0x578 / 0x579` | UI 启用、可见标志 |
| `state + 0xEC` | 菜单选择后触发的事件 |
| `state + 0x10C` | 读取存档成功后重建地图的标志 |
| `state + 0x130` | 返回标题等独立目标的标志 |

`sub_431170` 是共享 UI 绘制入口。主精灵先由 `sub_43E740` 准备帧，再由 `sub_43E940` 绘制并推进帧计数和帧内延迟。像素路径为 `sub_43E9A0 -> sub_43EDC0 -> sub_4290A0 -> sub_429480`。`sub_4290A0` 还更新资源块信息，不能直接跳过整段精灵绘制。

补丁在系统菜单关闭、原地图快照有效、没有读档、返回标题或触发事件时，仅在返回遮屏对象的绘制期间屏蔽 `sub_429480` 的像素写入。菜单主背景和子元素继续走原绘制入口。精灵帧、资源块信息、延迟、结束标志和元素展开逻辑均由原函数推进。菜单销毁后再写入居中的灰度地图快照，随后反向恢复彩色。离开菜单的其他目标仍保留原遮屏绘制。

2026-10-09，用户指出上一轮修复在菜单元素展开期间过早显示灰度地图。原因是 `RuntimeUiObjectDraw` 同时拦截菜单主背景和遮屏对象。此次将拦截范围收窄至遮屏对象，灰度地图仅在菜单析构后的衔接阶段写入。

## 反向恢复与绘制顺序

固定界面关闭后，`sub_40B0B0` 将原地图绘制标志恢复，并重新设置当前地图；补丁从此开始反向过渡。普通菜单保留地图绘制对象，析构 `sub_4143F0` 后单独开始恢复。返回路径存在原生淡入时使用其亮度进度；原生效果已重置为正常或没有淡入时，使用 200 毫秒计时。计时从第一帧可见地图开始，兼容帧率分离和 `GetTickCount` 回绕。

主循环 `sub_44A970` 依次恢复队列、更新逻辑、绘制队列并上传画面。系统菜单析构 `sub_435620` 只设置队列恢复标志，地图在下一次 `sub_434830` 调用时恢复。补丁在菜单析构后立即保持居中的灰度快照，覆盖尚未恢复队列和地图尚未绘制的间隙，直到 `RuntimeMapEffect` 收到实际地图绘制，再推进反向渐变。普通菜单析构后也立即恢复灰度快照，避免已调度画面留下空白。

系统菜单和商店的原生淡出结束时，CPU 缓冲区仍按整幅地图布局保存。`sub_40B0A0` 停止绘制后，用同一份灰度快照居中保存中央区域，再开始绘制固定界面，避免等待第一帧界面期间中央地图与侧边错位。

地图停止绘制时，可能完全离开本帧绘制队列，不能依靠下一次地图 hook 来识别。上传准备同时检查当前地图的禁止绘制标志，取消原有 3 帧宽限；普通菜单存在时明确使用中央固定布局及相应鼠标坐标。普通菜单关闭后，跳过逻辑更新的帧保留上一帧中央布局，直到实际地图绘制恢复，避免将已居中的缓冲区提前按宽屏显示。

## 战斗恢复原有效果

随机遇敌 `sub_4035A0` 直接停止地图绘制、保存中央地图并调用 `sub_4322C0`，没有调用通用淡出函数。剧情战斗进入也调用同一个初始化函数。实际 FBX 特效由 `sub_42D030` 启动，`sub_42CF70` 绘制并推进动画。

2026-10-09 按用户实机反馈撤掉战斗初始化和 FBX 动画 hook，删除战斗的灰度帧进度。`0x37` 不再属于灰度菜单转场目标，战斗进入和退出沿用原函数与像素效果。侧边继续使用已有灰度地图填充；没有菜单命令的地图暂停会清除菜单转场，覆盖随机遇敌，避免残留状态影响战斗进出。

## 像素和性能

灰度终点与已有侧边填充一致：加权亮度 `(77R + 150G + 29B + 128) >> 8` 后减半。彩色权重从 15 递减至 0，返回时反向递增；每个通道按 `(channel * weight + gray * (15 - weight) + 7) / 15` 混合。

RGB555、RGB565 地图使用各自格式写回，侧边合成仍输出 RGB565。原始侧边和整幅地图快照保留彩色，避免多次渐变累积变暗。颜色查找表只在权重或格式变化时重建，固定界面停留期间直接复用侧边结果。地图快照在原有 CPU 地图绘制后、效果及鼠标和对话框绘制前保存。

补丁不读取 DirectDraw 后备表面，不增加表面锁定；全部处理在 CPU 缓冲区完成，最终仍合入游戏原有上传。

2026-10-09 的独立离屏基准使用 `tools/benchmark_castle_backdrop.c`，每组 24 帧、3 次采样，权重逐帧变化。转场组包含模拟新地图绘制、地图快照保存、颜色表更新和正常上传；固定菜单转场组额外包含固定画面合成。

| 路径 | 默认表面平均每帧 | 系统内存表面平均每帧 |
| --- | ---: | ---: |
| 仅上传 | 0.196 毫秒 | 0.108 毫秒 |
| 旧版读回搬移 | 19.848 毫秒 | 0.116 毫秒 |
| 固定界面合并上传 | 0.193 毫秒 | 0.127 毫秒 |
| 地图灰度渐变及上传 | 0.583 毫秒 | 0.493 毫秒 |
| 固定菜单灰度渐变及上传 | 0.661 毫秒 | 0.591 毫秒 |

本轮基准输出为 `analysis/castle_transition_benchmark_latest.txt`。菜单遮屏 hook、实际游戏逻辑和素材绘制的代价未包含在该数据内，因此不代表实机帧率。

## 验证范围

- Visual Studio 18 2026 配置并构建 Win32、x64 启动器；两个 runtime 子项目均为 x86。
- `CastleTransitionTest` 覆盖菜单目标、战斗排除、受限脚本前瞻、换地图和分支排除、淡出保持及反向淡入、无原生淡入的计时恢复、中途关闭后的反向恢复、地图身份及读档状态清除，以及帧率分离下进出固定界面的布局。
- `CastleBackdropTest` 保留已有测试，并增加 RGB555/565 的 16 档转场、原图恢复、中央与侧边接缝、正负行距和无效快照检查。
- `CastleRuntimeTransitionTest` 直接包含 runtime hook 实现，仅将游戏全局地址和原函数替换为模拟对象及回调。逐帧核对菜单关闭阶段保留菜单背景和子元素、遮屏像素被屏蔽、原生动画计数继续推进；菜单销毁后才显示灰度地图，并覆盖地图首帧前的空绘制间隙。测试包含 RGB555/565、普通菜单计时返回、帧率分离，以及读档、标题、事件和新地图继续使用原路径，不加载或调用游戏。
- 离屏基准核对合并上传和旧版的中央、侧边像素一致。
- 独立 x86 程序 `tools/verify_castle_transition_hooks.c` 通过 `SEC_IMAGE` 映射原始文件，12 个新 hook 均可创建 MinHook trampoline，并成功启用、禁用和卸载；没有执行游戏入口、导入或游戏函数。原始输出为 `analysis/castle_transition_hook_probe.txt`。
- 读取 PE 头确认 Win32、x64 启动器位数及两个 runtime 的 x86 位数；分析与验证后原始文件 SHA-256 不变。
- 不自动启动游戏；菜单和战斗的实际视觉衔接、战斗结算返回、读档换地图、鼠标命中及 Bink 前后仍需人工实机验收。
