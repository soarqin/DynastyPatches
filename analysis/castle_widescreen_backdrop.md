# Castle 宽屏地图侧边填充

分析日期：2026-10-05。基准文件为 `E:\Games\Dynasty\Castle\exe\RPG.exe`，SHA-256 为 `8294839343b1a7845ddae31ed16216b05850efd39a742e5ca7701aadca97287f`。

使用 Windows 注册表找到的 IDA Pro 9.4，通过 Python `idapro` 分析 `build/ida-castle-backdrop/` 下的副本。辅助脚本为 `tools/ida_castle_widescreen_backdrop.py`，原始输出为 `analysis/castle_widescreen_backdrop_ida.txt`。分析前后校验原始文件哈希，未运行 `idat` 或游戏进程。

## 绘制与缓存时机

`sub_40B050` 为地图对象的绘制入口。`scene + 0x219` 非零时，函数直接返回，不绘制地图；进入函数本身不能作为地图帧的唯一判据。

正常地图帧的顺序为：

```text
sub_44B500                 临时应用镜头抖动
sub_407020 / sub_40ADE0    特殊地图或地图对象绘制
0x0040B07D                call sub_406DA0
sub_44B590                 恢复镜头抖动
sub_403E30                 转场像素效果
sub_404800                 对话框、头像和文字
sub_408810                 地图鼠标
```

缓存钩子位于 `0x0040B07D`，在原始调用执行前保存 CPU 缓冲区两侧的地图像素，因此不会缓存对话框、鼠标和后续转场修改。该位置原始字节为 `E8 1E BD FF FF`，运行时安装 MinHook 前逐字节校验。NASM 钩子保存通用寄存器和 EFLAGS，将仍由 `ESI` 保存的地图对象传入 C 函数，再跳入 MinHook 生成的 trampoline。

地图入口保留原有地图帧标记，但仅在 `scene + 0x219 == 0` 时设置。被明确禁止绘制的帧立即切换到固定界面合成，避免 60/20 帧率分离中的地图状态宽限把菜单错判为地图。

## 缓冲区与颜色格式

`sub_405960` 分配 CPU 缓冲区，`sub_406330 -> sub_44CBD3` 将可见区域复制到 DirectDraw 后备表面。字段来源如下：

| renderer 偏移 | 含义 |
| --- | --- |
| `+0x08` | DirectDraw 后备表面 |
| `+0x14` | 游戏已有临时表面 |
| `+0x28` | 显示模式记录，`+4/+8` 为可见宽高 |
| `+0x3C` | CPU 像素格式，`15` 为 RGB555，`16` 为 RGB565 |
| `+0x5C/+0x60` | CPU 缓冲区高度、行宽，单位为像素 |
| `+0x64` | 每像素字节数 |
| `+0x68` | CPU 缓冲区地址 |
| `+0x6C/+0x70` | 缓冲区水平、垂直边缘偏移 |

可见区域为 `864 × 480`，中央固定界面为 `640 × 480`，两侧各为 `112 × 480`。侧边缓存保存可见地图的 `[0,112)` 和 `[752,864)`，原始像素数据共 `215040` 字节。2026-10-09 增加双向灰度转场后，同时保留整幅原始地图快照和侧边转换结果，详见 [宽屏双向转场](castle_widescreen_transition.md)。保存前验证像素大小、格式、模式宽高、行宽、边缘偏移和总尺寸，防止使用越界区域。

首次合成固定界面时，将缓存转为灰度并降低亮度：

```text
luminance = (77 * R + 150 * G + 29 * B + 128) >> 8
gray = luminance / 2
```

输出转换为 RGB565。原始侧边像素保持彩色，转换结果按地图缓存和渐变权重复用；固定界面停留期间不重复转换。固定界面合成钩子位于游戏原有的 `sub_406330 -> sub_44CBD3` 上传步骤：表面已由游戏锁定，中央像素直接从 CPU 缓冲区写到 `[112,752)`，同时写入两侧缓存。支持负行距和行尾填充；菜单和战斗的界面像素不参与灰度处理。

`sub_44CBD3` 的函数地址为 `0x0044CBD3`，原始入口字节为 `55 8B EC 83 EC 10 53 56 57`。Python `idapro` 确认其仅有 `sub_406330` 内的 3 个调用点；窗口分支在 `0x0040649B` 调用，参数提供 CPU 像素源、边缘偏移、已锁定的后备表面地址和实际行距。钩子校验参数后取代本次全幅上传，地图和不匹配路径继续调用 MinHook trampoline。场景状态在上传前处理一次，最终呈现不会重复消费地图标记。

## 生命周期与恢复

缓存绑定 renderer、CPU 源地址和地图对象，不持有游戏 COM 表面的引用。`sub_40AF10` 在地图对象析构时释放 `scene + 0x280` 的地图资源；菜单和战斗只停止地图绘制，保留地图对象。

资源释放钩子位于 `0x0040AF10`，预期字节为 `56 57 8B F9 8B B7 80 02 00 00`。释放缓存所属对象时使缓存失效；旧对象的延迟析构不清除新地图缓存。

首次加载尚无地图或源缓冲区改变时，上传中央画面并填充黑边。无效源区域或行距在写入前返回原始路径。表面锁定、丢失恢复和解锁沿用游戏原有流程；补丁不进行额外表面锁定，也不读取后备表面。CPU 缓存不会因 DirectDraw 表面重新创建而失效。

Bink 保持既有独立呈现路径。输入命中仍限定在中央固定界面，侧边不参与游戏输入。

## 4:3 场景卡顿的复现与修复

2026-10-05，用户反馈菜单、战斗场景在新增地图侧边后变卡。上一版在游戏完成全幅上传后，再次锁定后备表面，用 `memmove` 从表面读取中央像素并向右移动；该读回在默认 DirectDraw 表面上代价较高。

使用 `tools/benchmark_castle_backdrop.c` 创建 `864 × 480` 的 RGB565 离屏表面，复现 `sub_406330` 的临时表面 `Blt`、锁定上传、解锁和最终 `Blt`，分别测量仅上传、上一版合成和合并上传。程序不创建游戏窗口或运行 `RPG.exe`，每组预热 2 帧、测量 24 帧，重复 3 组。

| 表面 | 仅上传，平均每帧 | 上一版，平均每帧 | 合并上传，平均每帧 |
| --- | ---: | ---: | ---: |
| 默认分配，与游戏相同 | 0.201 毫秒 | 20.006 毫秒 | 0.202 毫秒 |
| 显式系统内存 | 0.108 毫秒 | 0.119 毫秒 | 0.113 毫秒 |

上一版默认表面的像素搬移平均耗时 19.650 毫秒；额外锁定约 0.015 毫秒，解锁约 0.030 毫秒。主要耗时来自读回后备表面，而不是灰度转换或锁定调用。修复将合成并入已经锁定的上传步骤，保留灰度地图背景并消除读回。基准在计时结束后逐行验证两种合成结果的中央像素和左右灰度侧边完全一致。该数字属于本机离屏基准，不代表实际游戏帧率。原始测速输出保存在 `analysis/castle_widescreen_backdrop_benchmark.txt`。
